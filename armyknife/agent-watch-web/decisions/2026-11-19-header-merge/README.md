# 会話のヘッダーの Merge の置き場所

PC の会話のヘッダーでは、PR のボタンの右に Merge を常に出していた。CI が失敗していてマージできないときも出ていた。PR が複数あると、どの PR をマージするのか分からなかった。スマホの PR のシートの下にも、Merge #<n> が常に出ていた。

## 案

- A: ヘッダーの Merge をなくし、PR の一覧 (PC はポップオーバー、スマホはシート) で、マージできる PR の行の右端に Merge を置く。マージできない行には理由を出す。
- B: ヘッダーの Merge をなくし、PR の一覧の下に、このブランチの PR の Merge を置く。
- C: PR の一覧は今のままにし、このブランチの PR をマージできるときだけ、ヘッダーに Merge を出す。

## 採用した案

A と C を合わせる。PR の一覧では、マージできる PR の行に Merge を出し、マージできない行には理由を出す。PC のヘッダーの Merge は残し、このブランチの PR をマージできるときだけ出す。スマホのシートの下の Merge #<n> はなくし、Close だけを残す。スマホのヘッダーには Merge を置かない。

## 理由

- 行に Merge があるので、どの PR をマージするのかが分かる。
- PR が複数あっても、それぞれをマージできる。
- マージできない行には、その理由が出る。
- よくある、マージできる PR が 1 つだけのときは、ヘッダーの Merge から 1 回でマージできる。マージできないときはヘッダーの Merge が消える。
- B は、別の場所で開いた PR をマージできない。
