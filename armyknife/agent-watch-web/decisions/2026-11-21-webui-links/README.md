# 会話の中の web UI のリンク

会話の中のリンクの URL が登録済みの web UI の URL のとき、ふつうのリンクと同じ見た目で、押すと新しいブラウザのタブで開いていた。どのリンクがどの web UI のタブに行くのか分からなかった。

問いは 3 つで、それぞれ案を比べた。

## 見分け方

- 見分けない: ふつうのリンクと同じ見た目のままにする。
- パネルのアイコンを付ける: リンクの後ろに状況パネルの形のアイコンを出す。
- web UI の名前を添える: リンクの後ろに開く先のタブ名のチップを出す。

web UI の名前を添えるを選んだ。PC と iPhone で同じにする。

- 困りごとは「どのリンクがどれか」なので、開く先の名前まで見せる。
- crit と canvas のように web UI が複数あっても区別できる。アイコンだけでは区別できない。
- リンクが多いメッセージで文字が増えることは受け入れる。

## 押したときの動き

- 状況パネルで開く: パネルを開いて web UI のタブに切り替える。
- web UI を全画面で開く: web UI だけを画面いっぱいに出す。

web UI を全画面で開くを選んだ。ユーザーのコメントは「crit と同じでよい」。

- PC は、crit のレビュー待ちの帯の Review in crit と同じく、watch-web の中でその web UI のタブを全画面 (⛶) で開く。↙ で状況パネルに戻る。
- iPhone は、タブのない web UI だけのページを会話の上に重ねる。戻るで会話に戻る。
- crit と動きをそろえ、web UI を開く手段ごとに違う動きを覚えなくて済むようにする。会話が隠れて読みながら比べられないことは受け入れる。

## 新しいタブで開く手段

- web UI のヘッダーから開く: 会話のリンクは変えず、開いたあとの web UI のヘッダーから新しいタブを開く。
- ⌘ クリック・長押しで開く: PC は ⌘ クリック、iPhone は長押しのシートから新しいタブを開く。
- リンクの横にボタンを出す: 新しいタブで開く ↗ をリンクの横に置く。

web UI のヘッダーから開くを選んだ。ユーザーのコメントは「PC でも watch-web 内で開くべき。crit と同じで」。

- 会話のリンクからはブラウザの新しいタブを出さず、PC でも iPhone でも watch-web の中で開く。crit も同じ。
- 新しいタブへは、web UI のヘッダーの URL (PC) と ↗ (iPhone) からだけ開く。どちらも今あり、足すものがない。
- 一度 watch-web の中で開いてからでないと新しいタブにできないことは受け入れる。
