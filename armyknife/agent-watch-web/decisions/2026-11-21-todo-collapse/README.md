# すぐに確かめられない to-do を畳む

to-do カードはいつも見出し、タイトル、説明、コメント欄、Mark done / Reject の全部の大きさで出ていた。実機で通知を受け取るまで確かめられないような to-do も、その間ずっと会話の下を占め、Inbox の Needs action にも並んで数に入っていた。

問いは 3 つで、それぞれ案を比べた。

## 畳み方

- ユーザーがカードのボタンで畳む: 見出しの右の ⌃ で畳み、畳んだ行を押すと開く。
- Check later ボタンで畳む: Mark done / Reject の横に Check later を置き、押すと畳む。
- エージェントが登録時に畳んだ状態で出す: セッションが登録時に後で確かめる印を付けた to-do は、最初から畳んで出す。ユーザーは行を押せば開ける。

ユーザーがカードのボタンで畳むと、エージェントが登録時に畳んだ状態で出すの 2 つを組み合わせることにした。Check later ボタンは選ばなかった。

- ユーザーが、すぐに確かめられない to-do を自分で畳めるようにする。
- 実機での確認が要るかどうかは、エージェントが登録した時点で分かっていることが多い。その to-do は最初から畳んで出し、行に added folded と添える。
- ⌃ はカードの見た目をほとんど変えない。Check later はボタンが増え、iPhone では 3 つ並んで窮屈になる。

## 畳んだカードの見た目

- タイトルだけの 1 行: To-do · later の見出し、タイトル、⌄ の 1 行。行全体が開くボタン。
- タイトルと Mark done の 1 行: 行の右に Mark done を残し、開かずに終わらせられる。

タイトルだけの 1 行を選んだ。

- いちばん小さく、会話の流れを邪魔しない。
- Decision の閉じた行と同じ形で、会話の中で見慣れている。
- 確かめた後に終わらせるには一度開く必要があり、2 手かかることは受け入れる。

## Inbox での扱い

- 待ちとして数え続ける: Needs action に残し、プレビューに later と出す。
- Later にまとめる: Needs action から外し、今の ◷ Later の区分に入れる。
- 待ちの一覧の下に畳んだ区分を置く: Needs action から外し、そのすぐ下に To-do later の 1 行を置く。行に件数と先頭のタイトルを出し、押すと開く。

待ちの一覧の下に畳んだ区分を置くを選んだ。待ちの to-do が全部畳んであるセッションだけを Needs action から外す。畳んでいない待ちの to-do が 1 つでもあれば Needs action に残す。

- Needs action とその数を、今すぐ動けるものだけにする。
- 畳んでいない to-do は今すぐ動けるものなので、同じセッションに畳んだ to-do があっても Needs action から隠さない。
- 畳んだ to-do は Needs action のすぐ下に残り、見落としにくい。
- Later は時刻が来ると戻るが、to-do には戻る時刻がない。Later に入れると同じ区分で戻り方が違ってしまう。
- 区分が 1 つ増えることは受け入れる。畳んだ to-do がないときは出さない。
