# 返信欄の上にセッションの状態を出す

セッションが crit のレビューを待っていても、会話の画面からは分からなかった。crit を開くには、状況パネルを開き、crit のタブを選び、全画面にする 3 手が要った。実行中の行は working のときしか出ず、ほかの待ちの状態は会話の画面のどこにも出ていなかった。

## 案

- A: 返信欄の上辺に 1 行の帯を付ける。crit はテキストのリンクにする。
- B: 返信欄の上にチップを並べる。crit は白いボタンにする。
- C: 会話欄の幅いっぱいに帯を出す。2 行目に詳細を出し、crit は大きなボタンにする。

## 採用した案

C。返信欄のすぐ上に、会話欄の幅いっぱいの帯を出す。1 行目は状態で、2 行目は詳細 (質問の文、実行中のコマンド、タスク名) にする。出す状態は、実行中 (経過時間と実行中のツール)、バックグラウンドタスク、crit のレビュー待ち (バックグラウンドタスクと重なることもある)、質問、permission、ほかの待ち (agent status の waitingReason) の 6 つ。止まっているときは帯を出さない。crit のレビュー待ちは、needs_action で kind が Review、かつ webUis に crit があるときとする。古いセッションでは critUrl を使う。このとき帯に Review in crit のボタンを出し、今の crit の画面を 1 クリックで全画面で開く。スマホではボタンを幅いっぱい、高さ 44px にする。返信欄の下の使用状況の行はそのまま残す。

## 理由

- 2 行目に詳細まで出せる。
- スマホでは crit のボタンが幅いっぱいなので押しやすい。
- その代わり、会話が 1 行から 2 行ぶん短くなる。
