# 新しいセッションの画面をキーボードで操作する

- の画面は c で開けるようになり、↵ で始め、⇧↵ / ⌥↵ で改行するところまでは決まっていた。ディレクトリ、engine、モデルと effort、New worktree は押すとメニューが開くボタンで、マウスで押すしかなかった。⌘K の New session は ↑↓ で engine、⌥M でモデル、⌥W で worktree、⌫ でディレクトリを選び直す別の操作だった。

## 案

最初は今のボタンとメニューのままキーを足す案を 2 つの問いで出した。

各欄のキー (1. 各欄のキー):

- A: Tab で欄を順に移り、移った欄を ←→ か Space で変える。
- B: Tab 1 回で下のボタンの列に移り、そこでは d / e / m / w で開く。
- C: メッセージ欄の先頭で / を打つと /dir /engine /model /worktree を選べる。

キーの出し方 (2. キーの出し方):

- A: フォームの下に 1 行で、今いる場所のキーを並べる。
- B: 各ボタンの中に d / e / m / w を常に出す。
- C: ボタンの列に移ったときだけ、各ボタンに白地の文字を出す。

画面の形を見直す (4. 画面の形を見直す)。押すとメニューが開くボタンをやめる:

- A: 設定は欄の上に 4 行で値を全部並べ、Tab で入って ←→ で選ぶ。
- B: ⌘K の New session と同じ 1 本の入力と一覧にする。
- C: ディレクトリの候補に前回の設定を付け、選ぶだけで設定ごと決める。

## 採用した案

画面の形の B。+ の画面と ⌘K の New session を同じ部品にする。入力は 1 本で、ディレクトリを打って選ぶとチップになり、続けて最初のメッセージを打つ。下の一覧は START WITH (Claude Code、Codex) と OPTIONS (New worktree from main、Model、Effort) で、カーソルは入力に置いたまま ↑↓ で行を移り、↵ でその engine で始め、OPTIONS の行では ←→ で値を変える。iPhone は同じ部品でキーの案内を出さず、行と値を押して選ぶ。

あわせて、誤って閉じても書きかけの入力を消さない。ディレクトリ、打ちかけの文字、OPTIONS の値、最初のメッセージ、いた engine を、Esc や ‹ などどの閉じ方でもブラウザに残し、次に + か c か ⌘K の New session で開くと閉じたときのまま戻す。戻したときは入力の下に Restored your draft from 12:03 と Clear を出す。セッションを始めたら消す。

## 理由

- 1 と 2 の案は、どれもメニューを開くボタンのままキーを足していた。セレクトボックスそのものがキーボードと相性が悪いので、問いを立て直した。
- B は + と ⌘K が同じ操作になり、覚えるのは 1 つで済む。⌘K の ⌥M / ⌥W も要らなくなる。↑↓ が一覧に取られて複数行の文の中を上下に動けないことと、始める前と後で入力欄の場所が変わることは受け入れた。
- A は欄の上が 4 行ぶん高くなり、モデルが増えると Model の行が長くなる。C はいつもの設定なら速いが、候補の行が長く、変えるときは A と同じ 4 行も要る。
- ⌘K のようなパレットは閉じやすいので、閉じても書いたものが消えないようにした。
