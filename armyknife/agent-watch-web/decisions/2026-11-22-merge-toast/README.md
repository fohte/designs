# PC の toast の場所

PC の toast は画面全体の右下の少し上に浮いていた。右のパネルを閉じていると返信欄の上の帯 (Review in crit) と返信欄に重なり、開いているとパネルの一覧の上に浮いて、どの線にも揃っていなかった。会話の最後にも同じ Merging PR #<n> の 1 行が出ていた。iPhone の toast (返信欄の上) は変えない。

## 案

- A: 会話の欄の右下に置き、右端を返信欄、下端を返信欄の上の帯に揃える。
- B: Merge したセッションを開いている間は toast を出さない (失敗は出す)。別の画面に移ったら A の場所に出す。
- C: 会話の欄の右上、ヘッダーのすぐ下 (Merging… のボタンの真下) に出す。
- D: 画面全体の右下の角 (右と下から 16px) に出す。
- E: D と同じ場所にし、会話の最後の 1 行をなくす。
- F / G / H: D で返信欄に重なるときの扱い。F は D のまま、G は返信欄が右下にあるときだけ toast を上げる、H は toast が出ている間だけ返信欄を上げる。
- I: 画面全体の右上 (右から 16px、会話のヘッダーより下の 84px) に出す。
- J: 画面全体の左下 (左と下から 16px) に出す。

## 採用した案

J。toast はどの画面でも、右のパネルを開いていても、画面全体の左下 (左と下から 16px) に出す。幅は 360px のまま、2 つ以上は上に積む (新しいものが一番下)。会話の最後の 1 行も残す。

## 理由

- toast は画面全体への通知なので、会話の欄などセッションの区画の中には置かない。
- 右上の案 (I) は、会話のヘッダーより下に下げると位置が浮いて見えた。
- 左下は重なりが一番少ない。隠すのは Nav の quota や一覧の端で、返信欄の送信ボタンやヘッダーのボタンは隠さない。
- 会話の最後の 1 行を残すと、toast が消えたあとも会話の中で進み具合が分かる。
