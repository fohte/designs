# draft の承認の操作

Review タブでは、frontmatter の submit や steps.ready-for-translation が説明のないチェックボックスで並び、チェックすると何が起きるのかが分からなかった。

## 案

- A: 各チェックボックスに、終わったときに何が起きるかを書き、Finish のボタン名を選んだ内容に合わせて変える。
- B: チェックボックスをやめ、種類ごとの終わり方をボタンにする (例: issue のコメントは Send back / Post comment)。押すと保存してエディタを閉じ、あとはセッションが動く。
- C: ボタンは書いてあるとおりにすぐ実行する。Post comment はその場でコメントを投稿し、Create PR はその場で PR を作る。Send back は今までどおり編集内容をセッションに返す。

## 採用した案

C。

- 英語で PR を書く repo の PR draft は、日本語の draft を承認して翻訳に回し、英語の draft で Create PR を押す 2 段にする。段の位置は 1 Review · 2 Translate · 3 Create の印で出し、選択肢には見せない。
- 日本語で PR を書く repo は Create PR だけにする。

## 理由

- B に対して、Post comment と書いてあるなら押したらそのまま投稿すべきで、翻訳は選ぶものではなく必ず通る順番だという指摘を受けた。
- 1 回押せば、ボタンに書いてあることが起きる。
- 押したあとに取り消せないので、実装では押し間違えたときの扱いと、処理中や失敗したときの見せ方と再実行で重複しないことを確かめる。
