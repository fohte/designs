# 一覧の省略表示

セッションの一覧 (Recent、Inbox、Board、Tree) では、repo が縮まずにタスクを押し出し、狭い Inbox と iPhone ではタスク番号まで消えていた。Recent、Board、Tree の 3 行目では repo が右端で … なしに切れ、後ろの repo 名の方が消えていた。切れた文字の全文を見る手段もなかった。

## 案

1 行に入らないときの縮め方:

- A: repo やブランチを先に … で縮め、タイトルとタスク名を残す。repo は「…/notification-service」、ブランチは「⑂ fix-…」まで縮む。マウスを置くと全文を出す。
- B: 入らないものは … で切らず、丸ごと消す (engine、repo の順。3 行目はブランチ)。
- C: 入らないものは次の行へ送る。

repo 名の縮め方:

- A: org を … にして repo 名を残す。入るときは「example/notification-service」、入らないときは「…/notification-service」。
- B: 一覧では org を出さず、どの幅でも repo 名だけにする。
- C: 真ん中を … にして前と後ろを残す (「example/o…ability」)。

一覧の並びを会話のヘッダーにそろえるか:

- A: そろえない。一覧はタスクが先で repo から縮め、ヘッダーは repo が先でタスク名から縮める (今のまま)。
- B: 一覧もヘッダーに合わせて repo を先にし、タスク名から縮める。

## 採用した案

3 つとも A。

## 理由

- A は行の高さが変わらず、タイトルとタスク名が最後まで残る。B は狭い Inbox と iPhone で repo が消え、消えたことにも気づけない。C は行の高さがそろわず、一覧に入る件数が減る。
- org を … にすれば repo 名は残り、幅があれば会話のヘッダーと同じ org つきの書き方になる。B は別の org にある同じ名前の repo を見分けられず、C は iPhone で repo 名が読めない形になる。
- 一覧で一番読みたいのはタスクで、今の見慣れた並びのまま残せる。repo を先にすると、Inbox ではタスク名が先に欠け、iPhone では「#2048 通」まで縮む。
