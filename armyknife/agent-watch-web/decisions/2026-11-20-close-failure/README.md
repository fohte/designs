# セッションを閉じる操作が失敗したときの見せ方

Close の失敗 (エラーの文と Close and keep worktree) は Inbox の一覧のいちばん上にしか出ず、一覧をスクロールしているときや会話を見ているとき、iPhone では目に入らなかった。失敗の理由は 1 つしか出ないので、コミットしていない変更、merge していないブランチ、動いているプロセスのうち、ほかに何が残っているかは直して閉じ直すまで分からなかった。

## 案

- A: 失敗のトースト、Activity の行、会話の 1 行に、残っているものと Close and keep worktree を足す。どこから閉じても同じ場所に出す。
- B: 押した場所 (Done の Close、⋯ の Close session…、Inbox の行) のそばのポップオーバーに出し、⋯ に赤い点を付ける。
- C: 3 つの確認を全部調べて、残っているものと残っていないものを ConfirmDialog の形で並べ、Close and keep worktree を選ばせる。
- D: 失敗したセッションの返信欄の上の帯を、赤い失敗の帯に置き換える。
- E: 失敗したら、確認と同じ ConfirmDialog を失敗の内容で開き直す。
- 組み合わせとして、A と B (見えるときは押した場所、見えないときはトースト)、A の場所に C の中身を出す形も挙げた。

## 採用した案

A + C の中身。失敗はトースト (PC は右下、iPhone は返信欄の上)、会話の 1 行、Activity に出す。中身は 3 つの確認の結果で、トーストと会話の 1 行には残っているものの要約と Close and keep worktree、Retry を出し、Activity にはファイル、ブランチと PR、pid とプロセス名を全部並べ、Open in terminal も置く。トーストが高くなりすぎないよう、全部の一覧は Activity にだけ出す。確認の code がないエラーは、今までどおりメッセージと Retry だけにする。

## 理由

- Close はヘッダー、⋯、Inbox の e、⌘K のどこからでも始まり、確認したあとは裏で動くので、失敗が返るころには押した場所は残っていない。出す場所はトーストと Activity にまとめる。
- 一度で残っているものが全部分かれば、1 つ直しては次の確認で失敗する、を繰り返さずに済む。
- そのために、Close の API が 3 つの確認をすべて実行し、結果 (コミットしていないファイル、ブランチが merge 済みか、動いているプロセス) をまとめて返すように変える必要がある。
