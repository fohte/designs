# Merge の入口

PC の会話のヘッダーには、PR のボタンの右に Merge があり、PR の一覧 (ポップオーバー) の行にも同じ PR の Merge があった。同じ PR の Merge が 2 つあり、マージ中はどちらも Merging… になった。Done のセッションでは Merging… と Close がヘッダーで隣り合った。iPhone はヘッダーに Merge がなく、PR のシートの行だけだった。

## 案

- A: Merge は PR の一覧の行だけに置き、ヘッダーの Merge をなくす。PR のボタンに状態の印 (マージ中、失敗、マージ済み) を付ける。
- B: このブランチの PR が 1 つでマージできるとき、PR のボタンを「Merge #<n> | ▾」の分割ボタンにする。PR が複数ならボタンは戻り、Merge は一覧の行に出る。Done の Close は ⋯ に入れる。
- C: 返信欄の上の帯に Merge を出し、PR の一覧は見るだけにする。帯は Ready to merge と Merge、Merging…、Merge failed と Retry に変わる。
- A+C: A の PR のボタンの印と、C の帯を合わせる。

## 採用した案

A+C に、A の PR の一覧の行の Merge を加える。

- ヘッダーには PR のボタンだけを置き、Merge を置かない。PR のボタンの印でマージ中 (青の回転) と失敗 (赤の ! と赤枠) を出す。PC ではアイコンの右に並べ、iPhone では角に載せる。Done の Close はヘッダーに残す。
- 返信欄の上に Merge の帯を出す。Merge、Merging…、Merge failed と Retry に変わる。マージできる PR が複数なら帯に行を重ね、Question や crit の帯とは縦に積む。iPhone では長い失敗の理由を … で切る。
- PR の一覧 (PC はポップオーバー、iPhone はシート) でも、マージできる行に Merge を置く。帯と同じ PR を指し、同じ状態 (Merging…、Retry、Queued) を出す。マージできない行には理由を出す。
- マージ済みでは何も出さない。帯も印も消え、一覧の行にだけ Merged と出る。

## 理由

- 帯は会話を読んでいるときの入口、一覧の行は PR を見比べているときの入口になる。どちらからでもマージできる。
- 帯は返信欄のすぐ上にあり、会話を読んでいる場所の近くに出る。PC と iPhone で同じ場所、同じ大きさのボタンになり、失敗の理由も書ける。
- 帯を見ていなくても、ヘッダーの印でマージ中と失敗が分かる。
- マージ済みの表示はいらない。出すと画面が騒がしくなるだけなので、帯も印も消す。
