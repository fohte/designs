# 待っているセッション

他の作業 (PR のマージ、CI など) を待っているセッションも In progress に入り、作業中と同じ青い点と「Working」で出ていた。tq の優先度順に並ぶので、待っている行が In progress の先頭を占め、動いている行が「N more」に隠れることもあった。

## 案

一覧での分け方:

- A: In progress の上に「Waiting」の区分を分ける。Inbox は Later の下に「Waiting 3」、Board は各列の Needs action と In progress の間に「Waiting」の小見出し、iPhone は「Waiting 3 ⌄」の行を足す。
- B: In progress のまま、印と待っている内容の行で見分ける。

待っている印:

- A: 灰色の四角 (会話の下の帯の Waiting と同じ印)。
- B: 灰色の砂時計。

どちらの分け方でも、待っている行は 2 行目に待っている内容 (例「PR のマージ待ち」) を出す。

## 採用した案

分け方は A、印は B (灰色の砂時計)。会話の下の帯の Waiting の印も砂時計に揃える。

## 理由

- 区分を分ければ「なぜ In progress なのか」という疑問が消え、動いている行が待っている行に押し出されない。
- 四角では意味が読めない。砂時計なら小さくても待っていると読め、帯も揃えれば一覧から会話に移っても同じ状態だと分かる。
