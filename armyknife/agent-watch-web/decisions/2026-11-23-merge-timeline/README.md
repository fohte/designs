# 会話の中の結果の行

会話には Merge や Close の結果を Merged PR #2049 · 12:03 のような 1 行で残している。この行は会話の最後、いちばん新しいメッセージの下に出ていて、そのあとメッセージが来ても下に残り続けた。「この部分 (Merged PR の行) がずっと下にのこりつづけるのは嫌」「タイムラインとしてながれていけばいい」という声があった。

## 案

この canvas の案は、返信欄の上の Merge の帯を会話の中へ移すという読み違いから描いたもの。

- いつ出し、どう変わるか: A は PR を作った返答の下に出し、その場で書き換える。B はマージできるようになった時に一番下へ足し、その場で書き換える。C は状態が変わるたびに一番下へ 1 行足す。
- PR が多いとき: A は PR ごとに 1 行。B は 1 つの返答でできた PR を 1 つにまとめ、開くと一覧を出す。C はまとめた行に Merge all を置く。
- 返信欄の近く: A は何も出さず、ヘッダーの印は今のまま。B は帯が見えなくなったら返信欄の上に 1 行のまとめを出す。C は PR のボタンにマージできる数を出す。

どれも採用しなかった。困っていたのは結果の行が下に残ることで、返信欄の上の帯ではなかった。

## 採用した形

返信欄の上の帯 (Ready to merge と Merge) は今のまま残し、結果の行だけを会話の流れに入れる。

- 結果の行は操作を始めた時点の位置に置く。Merge を押すと、その時点の会話の一番下に Merging PR #2051… が出る。
- 同じ行をその場で結果に書き換える。Merged PR #2051、Merge of PR #2051 failed と Retry などになる。
- あとから来たメッセージはその行の下に並び、行はほかのメッセージと一緒に上へ流れる。
- 結果が複数あれば、それぞれ別の行として時刻の順にメッセージのあいだに並ぶ。
- PC と iPhone で同じにする。

## 理由

- 結果の行は、その時点に何が起きたかの記録になる。メッセージと同じように時刻の順に並んでいれば、会話を読み返したときに前後が分かる。
- 下に残り続けると、新しいメッセージより下に古い結果が出て、時刻の順が崩れる。結果が増えるほど会話の最後に行が溜まる。
- マージを待つ PR は返信欄の上の帯に出ているので、結果の行が下に残っていなくても、次にマージできる PR は見失わない。
